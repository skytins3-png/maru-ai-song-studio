# MARU 토크 방송 통합 운영 설계 · 2026-11-01

## 이번 단계에서 연결한 기능
- 방송 운영 센터: music-share/broadcast-center.html
- 형의 관리자 원곡 등록: music-share/admin.html. 권한 보유자만 공개 음악 업로드 가능.
- 청취자 사연 + 한국시간 희망 방송 시각: music-share/stories.html
- 사진·영상·자작곡·외부곡 검토 신청서: music-share/media-proposal.html. 현재 실제 파일 업로드는 아님.
- 웹 토크 라디오: music-share/radio.html
- Android 앱의 운영 센터 열기: 별도 저장소 개발 브랜치에 구현.
- STORY 이슈는 기존 검사·수동 승인 뒤에만 curated approved-stories.json으로 복사. 희망 시각 KST를 UTC로 변환하고 실제 웹 라디오 재생 세션 중 요청 이후 30분 이내 토크 전환 지점에서만 읽음. 정확한 시각 보장 아님.
- MEDIA-REVIEW 이슈는 기존 라디오·음악 목록과 분리되어 자동 재생하지 않음.

## 토크 방송 추천
- 아환과 한 명의 고정 손님이 서로 짧게 공감·질문·답변. 새 사연이 있을 때 관련 대화를 하고, 이후 형의 원곡을 들려주기.
- 반복된 동일한 대화, 과도한 AI 출연 인원, 긴 독백, 승인되지 않은 외부 노래와 영상, 부적절한 유저 지시문 실행은 제외.
- 날씨·뉴스는 출처와 생성 시각을 확인하고 최신 사실이 아니면 최신이라고 소개하지 않기.
- 영상은 토크에 필요한 짧은 승인 클립만 활용. BIGO 화면 출력은 별도 검증 필요.

## 실제 파일 업로드/정확한 예약 무인 방송에 필요한 추가 서비스
1. 비공개 제출 API: 로그인 또는 제한된 일회용 토큰, CAPTCHA, 속도·용량 제한, 접근 제어, 암호화된 비공개 격리 버킷. GitHub Issues는 공개이므로 비공개 미디어 업로드 서버가 아님.
2. 파일 검사: scripts/scan_quarantined_media.py는 향후 서버에서 격리된 파일을 검사할 수 있는 출발점. 매직 바이트·크기, 필수 ClamAV, ffprobe 코덱·길이·해상도, SHA256를 검사. 통과 결과도 eligibleForBroadcast:false. 클라이언트는 이 도구를 직접 호출하지 않음. 실행 파일 샌드박스, 바이러스 정의 최신화, 리소스 상한, 이미지 재인코딩, 악성 압축 차단 필요.
3. 저작권·초상권: 원저작자, 음원 제작자, 영상 인물 동의, 플랫폼 방송/재배포/수익화 허락의 지역·기간·범위를 검증. Content ID 같은 자동 지문 검사로 법적 사용허가를 확정할 수 없음.
4. 승인 상태: quarantined → scan-passed → rights-pending → producer-approved → scheduled → played. 취소/삭제 및 이력/긴급 차단 필요.
5. 예약 서버: 항상 실행되는 스케줄러 + DB + 중복방지 트랜잭션. 희망 시각과 최종 확정 시각 별도 기록, 미송출 시 기록 및 사용자 알림. 브라우저만으로 잠금화면·무인 정확 시작/종료를 보장하지 못함.
6. BIGO 연동: 공식적으로 허용된 오디오 라우팅/방송 연동만 사용. 실제 청취자 출력과 자동 시작·종료는 두 번째 기기 검증 필수.
7. 개인정보: 보존·삭제·철회, 방송 공개 동의, 미성년자 보호, 신고, 백업 및 운영자 접근통제를 준비.

## 현재 한계
- 관리자만 공개 음원을 GitHub에 실제 등록 가능. 이전에 등록된 음원 수는 아직 0.
- 청취자 사연은 공개 GitHub Issue로 전송되며 GitHub 로그인과 최종 제출이 필요. 자동 승인이 아님.
- 청취자 미디어는 메타데이터 신청만; 실제 파일 전송·실시간 백신 검사·외부곡 다운로드 또는 재생은 미구현.
- 격리 파일 검사 모듈은 서버용 준비 코드이며 현 사이트에서 자동 실행되지 않음.
- 웹 라디오는 Start를 직접 누르고 브라우저가 활성화되어야 함. 정확한 예약 무인 BIGO 방송은 미구현.
