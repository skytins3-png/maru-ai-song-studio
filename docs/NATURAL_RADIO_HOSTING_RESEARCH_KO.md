# MARU RADIO 사람 같은 진행 대화 설계 · 2026-11-07

## 조사한 실제 라디오 제작 원칙

- WSLR, [Programmer Handbook](https://wslr.org/handbook/): 매 곡마다 장황한 멘트를 반복하지 않고 필요한 순간에만 말한다. 의도적인 짧은 침묵, 대화 같은 목소리, 종료 멘트와 곡 소개의 명확성.
- NCPR/NPR, [The Art of the Interview](https://www.northcountrypublicradio.org/news/npr/812934447/the-art-of-the-interview): 상대의 답을 듣고 이미 나온 이야기에서 후속 질문을 뽑는다. 감정적인 대답 앞에서 무조건 다음 질문으로 넘어가지 않는다.
- WDBX, [Talking on-air](https://www.wdbx.org/how-to/dj-training-talking-on-air/): 부자연스러운 아나운서 톤보다 평소의 속도와 말투, 소수의 간결한 전환 멘트.
- PRX, [Broadcast Clock](https://help.prx.org/hc/en-us/articles/203648790-Should-I-format-my-program-to-fit-a-broadcast-clock): 긴 프로그램은 오프닝, 음악, 대화, 전환, 클로징을 시간 기준으로 관리한다.
- BBC Academy, [Making news for radio or a podcast](https://downloads.bbc.co.uk/academy/academyfiles/Making%20news%20for%20radio%20or%20a%20podcast.pdf): 상황을 모르는 청취자에게 맥락을 간단히 설명하고, 현장음/대화/음악의 레벨을 분리한다.

원칙만 연구·적용했으며 방송국의 대본, 실제 인물 목소리, 저작권 있는 영상을 복제하지 않았다.

## 1차 구현된 실제 코드

`vocal-studio/radio-human-host.js`는 네트워크 요청 없이 브라우저 로컬에서 작동하는 **미리 작성된 가상 진행 대본**이다.

- 1곡째: 아환 짧은 인사 → 윤솔의 짧은 반응 → 첫 곡 소개.
- 2곡째부터: 한 사람이 소개하는 짧은 멘트 12종 순환. 매 곡마다 3명이 말을 나눠 갖는 기계적인 진행 제거.
- 곡이 끝난 뒤: 모든 곡에 장황한 감상평을 넣지 않음. 균형형은 2곡마다, 음악 중심형은 대부분의 곡에서 후일담을 생략.
- **균형형:** 3곡마다 가상 초대석 대화. **토크형:** 2곡마다. **음악형:** 무대와 원곡 중심.
- 초대석: 아환이 질문→윤솔이 반응→가상 게스트가 그 주제에 답→진행자가 음악으로 전환하는 3~4턴. 곡 종류(KR/CN/WEST/INSTR)에 따라 주제 교체.
- 각 TTS 발화 뒤 260~470ms의 자연스러운 호흡. 마이크/곡 음성은 기존 플레이어만 담당하고 겹치지 않게 순차 진행.
- 화면: 첫 멘트는 진행자 브릿지, 노래는 무대, 가상 초대석은 두 사람이 앉아 있는 장면으로 전환. 출연자 실제 얼굴/동영상은 사용자가 승인한 파일로만 표시.
- 제목을 출력할 때 제어 문자 및 `<`, `>` 등은 제거하여 그대로 HTML로 실행하지 않음.
- 30명의 가상 가수 설정과 제작 완료 현황은 따로 관리한다. **대본 출연은 실제 보컬 제작 완료를 의미하지 않음.**

## 1차 리허설 큐시트 예시 (총 5곡)

| 순서 | 진행 | 화면 |
| --- | --- | --- |
| ① | 아환 인사 → 윤솔 반응 → 곡 제목 → 원곡 | 브릿지→무대 |
| ② | 한 문장으로 2곡째 소개 → 원곡 | 브릿지→무대 |
| ③ | 곡 제목 → 원곡 → 짧은 여운 → 가상 초대석 4턴 | 무대→초대석 |
| ④ | 윤솔 한 문장으로 소개 → 원곡 | 브릿지→무대 |
| ⑤ | 아환 한 문장으로 소개 → 원곡 → 여운 멘트 | 브릿지→무대 |

## 다음 단계와 한계

이 구현은 **진짜 사람이 실시간으로 말하는 AI 모델이 아니라**, 텍스트가 반복되는 것을 줄인 **가상 TTS 방송 리허설**이다. 이어지는 화제는 준비된 대화에 한정된다. 청취자의 음성/댓글을 실제로 읽고 의미를 기억해 답하거나, AI가 새로운 대본을 즉석에서 생성하는 기능은 아직 없다. 인터넷에서 지식을 무단 수집하거나 자동 학습하지 않는다.

실제 사람 같은 장시간 인터뷰로 발전시키려면 승인된 사연 데이터와 연결된 대화 상태·맥락 메모리, 실시간 음성 인식/응답 엔진, 끼어들기 처리, 실패시 기존 곡으로 복귀, 모니터링 및 진행자 승인 단계가 필요하다. BIGO 오디오 LIVE 수신 여부 역시 별도의 2기기 청취 검증이 요구된다.
