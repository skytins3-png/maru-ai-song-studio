# 아환 LIVE STUDIO · 초대·대화·라이브 음악 방송국 V0.1 설계
2026-11-06 / 설계 단계. 앱 설치본이나 실제 음성 생성 결과가 아님.

## 0. 방송의 정의
아환(호스트)이 실존 인물(명시적 초대 및 동의) 또는 **가상 AI 가수 30명 중 1명**을 초대한다. 근황·제작 스토리와 청취자 질문을 나누고 **승인받은 실제 녹음 음성/원곡을 재생**하며, 노래 뒤에 감상·신청곡·다음 주제를 연결한다. 일회성 DJ TTS 반복 방송이 아니다.

- 기존 선정 목록: 남 20명·여 10명 / 30명. 30명 이름·원고는 사용자 개인 Library의 MARU-30-Original-Songs.md 자료를 기준으로 매핑하고, 이 공개 저장소에 실제 보컬 원본을 올리지 않는다.
- Suno 원본 107곡 분석 결과: 107 정상, 중복 2개, 105개 고유 파일. 현재 어떤 목소리도 독립 30개 학습 모델로 검증된 것은 아니다.
- 휴대폰 기본 TTS나 무단 복제 음성을 **금지**한다. 클립이 없으면 여성/남성 기본 TTS를 임의로 대신 송출하지 않고 '오디오 미등록'을 표시한다.
- Suno의 Persona는 **노래의 보컬/스타일 기반으로 새 곡 생성**에 쓰이는 기능이지 실시간 말하기나 30개 독립 음성 모델 생성 보증이 아니다.
- Suno의 새 Voices는 실제 본인 목소리와 본인 읽기 인증을 요구하므로 Suno가 생성한 가상 보컬을 실제 사람으로 사칭하여 인증하지 않는다.

## 1. 참고한 현재 방송 포맷
- NPR World Cafe: 음악가 인터뷰 및 공연 → 아환 '초대 인사/근황/음악 이야기/대표곡'.
- BBC Radio 1 Live Lounge: 공연·인터뷰 → 대표곡 및 특별 스튜디오 세션(타인 커버곡은 별도 공연·저작권 허락 없으면 제외).
- MBC 배철수 음악캠프: 사연·신청곡·선곡표/보이는 라디오 → 청취자 접수·승인·곡 선택.
- 독자 콘셉트: 한 회에 한 명의 **가상 30인 가수**를 중심 게스트로, 각자 다른 작품 기록과 상호작용하며 '음악 제작을 둘러싼 근황'을 연속 이야기로 전개. 같은 화제를 30명이 똑같이 말하지 않음.

## 2. 방송 50분 편성 예시
| 시간 | 코너 | 담당 | 출처 |
|---|---|---|---|
| 00:00–03:00 | 아환 첫 인사·오늘의 라인업 | 아환 본인 녹음 또는 승인 음성 클립 | host_voice |
| 03:00–10:00 | 오늘의 가상가수 초대·곡 작업 근황 | 한 명의 가상 AI 가수, **가상 인물**임을 화면 표시 | approved_talk_audio |
| 10:00–14:30 | 첫 대표곡 | 저작권 검증된 Suno 원곡 | song_audio |
| 14:30–19:00 | 가사 뒷이야기·사연 1개 | 실제 사실로 확인된 사용자 제출이나 명백한 창작 사연 | approved_talk_audio |
| 19:00–24:00 | 진짜 청취자의 질문과 답장 | 접수·방송공개 동의·익명화·운영자 승인 | approved_question |
| 24:00–29:00 | 가수의 두 번째 노래 | 같은 Persona 일관성 청음 후 승인한 곡 | song_audio |
| 29:00–39:00 | 실존 초대 손님 또는 제작 스토리 | 실존 손님 사전 동의/실시간 접속 또는 승인 녹음 | human_guest_or_fallback |
| 39:00–45:00 | 다음 손님 예고·한 곡 더 | 신규/다른 가수 원곡 | song_audio |
| 45:00–50:00 | 다음 회차 사연 초대·마무리 | 아환 본인 음성 | host_voice |

여백은 실제 답변·노래 길이에 맞게 유연하게 늘리고, 음악이 끊기면 안전한 승인된 배경음 파일 또는 무음으로 되돌아간다. 방송 길이를 정확히 채운다고 보장하지 않는다.

## 3. 화면 구조: 화면 하나
- 위: 지금 방송 중 / 가상 AI 가수 표시 / **LIVE 송출 여부 검증 전**.
- 가운데(화면을 꽉 채움): 토크 중 손님 승인 이미지/영상, 노래 중 개별 앨범 표지, 자료 없을 때 기본 배경. 1개 미디어만 표시.
- 아래: **초대**, **질문 받기**, **내가 말하기(실제 녹음 재생)**, **노래 시작**, **다음 코너**, **긴급 중단**.
- 측면 운영자용: 30명 가수, 오늘 출연자, 음성·노래·이미지·사연 라이브러리, 승인 상태, 재생 큐.
- 실존 게스트: 참여자 실명은 공개 동의 범위 안에서만 표시. 가명 기본.
- 가상 게스트: 시작·방송 중 계속 '가상 AI 가수' 표시. 사실이 아닌 가상 근황은 창작 스토리임을 명시.

## 4. 진행 엔진 (오디오 큐)
states:
  PREPARE -> INTRO -> INVITED_GUEST_TALK -> SONG_1 ->
  LISTENER_QA -> SONG_2 -> REAL_GUEST_OR_STORY -> SONG_3 -> OUTRO -> END
  모든 상태 -> PAUSED 또는 EMERGENCY_STOP

각 큐 아이템 필수 데이터:
  cue_id, media_kind(audio|video|image), artist_id(1..30 또는 null),
  is_fictional_ai, human_consent_record, source_local_uri,
  recording_origin, song_origin, right_to_broadcast,
  right_to_download_or_archive, approved_by, approved_at,
  expected_duration, play_at, fallback_id, takedown_flag

- 없는 파일·미승인 파일·금지된 파일은 **자동 재생하지 않는다**.
- 아이템이 끝나면 다음 방송 단계로 진행. 운영자가 '건너뛰기' 또는 '긴급 중단'할 수 있다.
- 곡이 시작되면 토크 오디오를 정지/페이드하고, 끝나면 진행 클립/대화로 복귀한다.
- 하나의 실제 오디오 믹서에서 음량 관리. 화면 잠금/BIGO 내부 송출 보장은 하지 않는다.
- 실시간 텍스트 댓글 → '문자 열람/운영자 승인'까지; 본인 동의 보컬로 음성 합성하는 별도 오디오 엔진이 없는 상태에서 억지로 TTS를 쓰지 않는다.
- 만약 향후 실시간 음성 대화 엔진을 붙인다면 실제 녹음의 권리/생체 음성 보호, 사전 검증, 지연·안전장치, 생성형 AI 공개 표시가 선행되어야 한다.

## 5. 가상가수의 '근황 이야기'가 거짓 뉴스가 되지 않게
가수 프로필은 role=fictional_ai를 고정, fictional_bio, song_catalog, persona_profile, approved_memories,
past_episode_index, personality_traits, question_bank, banned_claims로 구성한다.
'요즘 어떻게 지냈어요?'라고 물으면 실제 출연/여행/수상 등을 지어내지 않고,
최근 **등록된 신곡의 제작 과정**, 청취자 질문, 제작자 승인한 '가상 설정 속 근황'에 관해서만 말한다.
예: '(가상 설정) 지난주부터 오래된 편지에 관한 노래를 준비하고 있어요.'
청취자의 실제 사연은 허락 없이 AI 가수 기억/학습 데이터에 영구 저장하지 않는다.

## 6. 남성20·여성10 음성 파이프라인
(1) 원곡 파일 합법적 출처 및 Suno 생성 시점 구독/다운로드 권리 입증
(2) 중복 제거·후보 청음·출처/장르/보컬 유형 검토
(3) 보컬 stem 별도 분리 후 아티팩트·간주·화음 혼입 점검
(4) 1명당 최소 서로 다른 원곡 2개에서 음색 일관성 검증
(5) 보컬/스타일 계승은 Suno Persona 사용 가능 (비공개 권장)
(6) '새 문장을 실제로 말하는 음성'은 별도 승인된 녹음/음성 생성 모델이 있어야 함
(7) 미완료 모델을 완성된 30명이라고 광고 금지

판정 상태:
  NOT_IMPORTED -> SONG_AUDIO_VERIFIED -> VOCAL_STEM_REVIEWED ->
  PERSONA_CANDIDATE -> TWO_SONGS_COMPARED -> APPROVED_SINGING_IDENTITY
  토크 가능 여부는 별도: TALK_AUDIO_MISSING / APPROVED_TALK_CLIPS / REALTIME_VOICE_APPROVED

## 7. 법·안전 차단 규칙
1. Suno 2026-09-03 약관: 원곡 제작 당시 Pro/Premier 적격 여부 및 공식 다운로드 경로, 제3자 저작물/보컬 무단 도용 확인. '상업적 이용 허락'과 '한국 저작권 등록 인정'은 다름. 무료/Basic 곡, 조건에 따라 Remix는 상업 이용 제한 가능.
2. BIGO: 타인 저작권, 녹음, 영상, 기타 실연을 허락 없이 송출하지 않음. 실제 BIGO 내부 음성 출력은 별도 실기기 청취 테스트 필요.
3. AI 기본법: 실제와 혼동될 만한 생성 음성·영상과 가상 AI 출연을 사전 고지하고 지속 표기. '사람이 생방송하는 가수'처럼 오인시키지 않음.
4. 실존 출연자: 방송 공개/녹음/재방송/다운로드/AI 학습·음색 변환 권한을 **각각 분리해서** 받음. AI 음성 복제와 얼굴 영상 변환은 원칙적으로 기본 OFF. 삭제/철회 처리.
5. 청취자 업로드: 비공개 격리 → 악성 파일 검사 → 인권·초상권·저작권 검토 → 관리자 승인 → 방송 예약. 공개 GitHub Issue는 개인 사연 파일 저장처 아님.
6. 선물·좋아요·시청자 이름은 실제 확인된 이벤트만 언급, 자동 수집이 불가능하면 가상 수치를 만들지 않음.
7. Suno / BIGO 서비스 화면 자동 스크래핑, 크랙 다운로드, Stream ripping, 비공식 송출 API와 접근성 무단 조작 금지.
8. 법률상 위험을 줄이는 설계이며, 법적 문제 완전 부재를 보장하는 법률 자문은 아님.

## 8. 가장 먼저 구현할 작동 범위
MVP-1: 아환 본인 승인 음성 1개 + 가상 가수 1명 승인 토크 녹음 3개
+ 권리 검증된 Suno 원곡 2개 + 승인 사연 1개로
'초대→5문답→노래→사연→다음 노래→마무리' 전체 미리듣기.
합격 조건: 구간 미중단, 재생·건너뛰기·되감기·중단, 미디어 교체/삭제, 0건 승인 시 안전 대기,
마이크/실기기 음성 출력 테스트. 모바일 기본 TTS 호출 0회.
MVP-2: 30명 가수 후보/실제 음성 검증 상태 관리와 30곡 재생 큐.
MVP-3: 동의받은 실제 게스트 초청과 청취자 참여(필요한 서버·플랫폼 허가 확인 이후).
MVP-4: 실시간 AI 음성 엔진이 합법·품질·실기기 송출 검증된 경우에만 도입.
