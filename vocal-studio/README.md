## 보컬 오디션 구현
- `audition.html`: 가수 후보 30명을 실제 노래 파일 2곡으로 오디션하는 독립 모바일 화면. 음원은 사용자가 선택한 경우 이 기기 IndexedDB에만 저장됨.
- `audition-policy.js`: SHA-256 파일 중복방지·곡당 45초 조건, 가창력 6분야 4점 이상/총점 26점 이상, 청취·음성모사 금지·방송권리·예명 사전 검토 등 필수 확인 조건.
- `audition.js`: MP3/WAV/M4A 등 로컬 파일 등록, 가수별 심사 및 결과 내보내기.
- **경고:** 로컬 자가 심사 합격 ≠ 공식 가수 제작 완료. 중앙 `production-status.json` 0/30과는 연동하지 않음. 법률 전문 검토·전문 음악 QA·BIGO 실송출은 아직 수행하지 않음.
- `node --test tests/vocal-audition.test.cjs`에서 통과/실패 기준 검사.

## 원본 음질 자동 분석
- `audio-qc.js`는 파일의 실제 PCM을 Web Audio로 디코딩하고 RMS(dBFS), Peak(dBFS), 클리핑 1% 초과 여부, DC offset, 모노/스테레오, 샘플레이트를 검사합니다. 매우 조용하거나 심하게 왜곡된 파일은 로컬 오디션 심사에서 통과할 수 없습니다.
- 이 자동 지표만으로 실제 음정, 노래 실력, 목소리 일관성, 저작권, 방송 허가를 증명하지 않습니다. 기존 등록 파일은 QC 메타데이터가 없으므로 다시 등록해야 합니다.

- 사용자가 이 채팅에서 받은 전곡 개인 청음키트 ZIP은 공개 GitHub에 올리지 않습니다. 압축 안에 105곡×2구간 미리듣기 210개와 파일명, 해시가 있습니다. 청음 평가와 두 곡 짝짓기(가수 30명 후보)를 JSON으로 내보낼 수 있습니다.

- `pairing-policy.js`는 T001~T105 원본 SHA 105개 및 후보 식별자 30개, 서로 다른 두 곡, 인간 청음·음색/발음/개성 4점 이상을 확인합니다. 이 검증은 **후보 2곡 선별 검토**일 뿐, 정식 가수 승인이나 동일 보컬의 음성학적 증명은 아닙니다.
- `make.html?artist=F3-01`처럼 후보 선택 링크를 열어 기존 Suno 생성 설정을 이어갈 수 있습니다. 현행 Suno API 연동은 없으며 무인 생성 불가. 정식 승인 상태 `production-status.json`은 변경하지 않습니다.
